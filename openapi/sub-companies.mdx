## Base

Base path: `/api/sub-companies`

Todos los endpoints requieren autenticacion. El CRUD usa permisos `sub-companies.*`; las descargas usan el permiso del modulo de datos exportado (`drivers.download`, `vehicles.download` o `cards.download`). El borrado desactiva el registro cambiando `status` a `inactive`.

## Alcance por compania

Requiere header `X-Company-Id: <companyId>`. Todas las operaciones quedan limitadas a esa compania. Si el acceso del usuario tiene `scopeKey: "subCompanyId"`, solo ve y opera esas subcompanias. En create se requiere alcance completo de compania.

## Listado

`GET /api/sub-companies`

Query params: `page`, `limit`, `search`, `all`, `status`, `companyId`.

`search` busca por `key`, `cardcloudSubaccountId`, `name`, `company.key` y `company.name`.

Para la columna Compania en front, usa `company.name` o `company.key + " · " + company.name`; no muestres `companyId` salvo en vistas tecnicas.

Response `200`: resultado paginado de `SubCompany` con `company` summary y sin `address`.

## Exportar subcompanias

`GET /api/sub-companies/export`

Requiere `sub-companies.read-list`.

Query params: acepta los mismos filtros de `GET /api/sub-companies` mas `format`.

`format`: `xlsx`, `excel`, `csv`, `txt` o `pdf`. Default `xlsx`.

Response `200`: archivo descargable. El backend aplica filtros y alcance igual que el listado, ignora paginacion y limita la exportacion a `5000` filas.

## Crear

`POST /api/sub-companies`

```json
{
    "companyId": "0ed7e7e1-2b6d-45cf-94c7-79bf03bbaf02",
    "key": "SUB001",
    "name": "Acme Norte",
    "status": "active",
    "isDefault": false,
    "address": {
        "city": "Monterrey",
        "state": "Nuevo Leon",
        "country": "MX"
    }
}
```

Requeridos: `companyId`, `key`, `name`. `companyId` debe apuntar a la compania activa enviada en `X-Company-Id`.

Opcionales: `status`, `isDefault`, `address`.

Al crear, el backend primero crea la subcuenta en Cardcloud con `ExternalId = company.key + "__" + key` y `Description = name`. Si Cardcloud falla o no devuelve un identificador de subcuenta valido, no se crea la `SubCompany` local. El `cardcloudSubaccountId` se guarda con el identificador devuelto por Cardcloud y no debe enviarse en el body de creacion.

Si `isDefault` se envia como `true`, la subcompania creada queda como predeterminada y el backend desmarca cualquier otra subcompania predeterminada de la misma compania en la misma transaccion.

Response `201`: `SubCompany` con `company` summary y `address`.

## Obtener

`GET /api/sub-companies/:id`

Path params: `id` UUID de la sub-compania.

Response `200`: `SubCompany` con `company` summary y `address`.

## Descargas

`GET /api/sub-companies/:id/drivers/download`

Permiso: `drivers.download`.

Descarga un archivo Excel (`.xlsx`) con los conductores de la sub-compania, vehiculos actualmente asignados y tarjetas vinculadas a esos vehiculos.

`GET /api/sub-companies/:id/vehicles/download`

Permiso: `vehicles.download`.

Descarga un archivo Excel (`.xlsx`) con los vehiculos de la sub-compania, combustible, conductor actual y tarjeta asignada.

`GET /api/sub-companies/:id/cards/download`

Permiso: `cards.download`.

Descarga un archivo Excel (`.xlsx`) con las tarjetas de la sub-compania, estado local, estado Cardcloud, vehiculo y combustible de diseno.

Las descargas respetan `X-Company-Id` y el scope por subcompania del usuario autenticado. Si la sub-compania no pertenece al alcance del usuario, responde como no encontrada o no autorizada segun el guard.

## Actualizar

`PATCH /api/sub-companies/:id`

Acepta `name`, `status`, `isDefault` y `address`, todos opcionales. No cambia `companyId`, `key` ni `cardcloudSubaccountId`.

`key` y `cardcloudSubaccountId` no son editables porque forman el vínculo con la subcuenta Cardcloud creada para la subcompania.

Si `isDefault` se actualiza a `true`, esa subcompania queda como predeterminada y el backend desmarca la predeterminada anterior de la misma compania.

Response `200`: `SubCompany` actualizada con `company` summary y `address`.

## Desactivar

`DELETE /api/sub-companies/:id`

Response `200`:

```json
{
    "id": "79d03f1d-3da4-478e-806e-75ef9d86c992",
    "status": "inactive"
}
```

## Notas para frontend

Este modulo tambien aplica las reglas CRUD de `Frontend Guidelines`: crear con campos visibles/derivados, editar solo campos documentados en `Actualizar`, confirmar desactivacion y refrescar el listado despues de cada mutacion.

Usa `GET /api/authentication/capabilities` para decidir entrada al menu y acciones visibles:

- Crear subcompania: `modules.subCompanies.actions.openCreate` y `modules.subCompanies.actions.create`.
- Pestañas de crear `Formulario` y `Direccion`: `modules.subCompanies.actions.openCreateForm` y `modules.subCompanies.actions.openCreateAddress`.
- Consultar listado: `modules.subCompanies.actions.readList`.
- Refrescar listado: `modules.subCompanies.actions.refreshList`.
- Configurar columnas: `modules.subCompanies.actions.configureColumns`.
- Exportar listado: `modules.subCompanies.actions.exportList`.
- Abrir detalle: `modules.subCompanies.actions.openDetail` u `modules.subCompanies.actions.openDetailDrawer`.
- Pestañas de detalle `Formulario` y `Direccion`: `modules.subCompanies.actions.openDetailForm` y `modules.subCompanies.actions.openDetailAddress`.
- Editar subcompania: `modules.subCompanies.actions.openEdit` u `modules.subCompanies.actions.openEditDrawer`.
- Pestañas de editar `Formulario` y `Direccion`: `modules.subCompanies.actions.openEditForm` y `modules.subCompanies.actions.openEditAddress`.
- Actualizar subcompania: `modules.subCompanies.actions.update`.
- Desactivar subcompania: `modules.subCompanies.actions.openDeactivate`, `modules.subCompanies.actions.openDeactivateDialog` o `modules.subCompanies.actions.deactivate`.
- Abrir drawer de datos relacionados: `modules.subCompanies.actions.openRelatedData`.
- Pestaña `Conductores`: `modules.subCompanies.actions.openRelatedDrivers`.
- Buscar conductores relacionados: `modules.subCompanies.actions.searchRelatedDrivers`.
- Descargar conductores: `modules.subCompanies.actions.downloadDrivers`.
- Pestaña `Vehiculos`: `modules.subCompanies.actions.openRelatedVehicles`.
- Buscar vehiculos relacionados: `modules.subCompanies.actions.searchRelatedVehicles`.
- Descargar vehiculos: `modules.subCompanies.actions.downloadVehicles`.
- Pestaña `Tarjetas`: `modules.subCompanies.actions.openRelatedCards`.
- Buscar tarjetas relacionadas: `modules.subCompanies.actions.searchRelatedCards`.
- Descargar tarjetas: `modules.subCompanies.actions.downloadCards`.

`configureColumns` es accion local de interfaz. `exportList` usa `GET /api/sub-companies/export` y se habilita cuando el usuario puede consultar el listado. `delete` en este modulo significa desactivar la subcompania, no borrado fisico. El drawer de datos relacionados solo tiene endpoints de descarga; si el front muestra busqueda/lista previa, debe alimentarla con datos ya cargados por el cliente o mantener estado vacio hasta implementar endpoints de consulta dedicados.

Si la pantalla muestra `Fondeos` desde una subcompania, tratalo como accion contextual de Cardcloud Transfers. La subcompania solo aporta `subCompanyId`; la autorizacion sale de `modules.cardcloudTransfers.actions.transfer`, `modules.cardcloudTransfers.actions.transferBulk`, `modules.cardcloudTransfers.actions.downloadTemplate` y `modules.cardcloudTransfers.actions.uploadExcel`. No uses permisos `sub-companies.*` para habilitar acciones que mueven fondos.

Este modulo siempre trabaja dentro de la compania seleccionada. El front debe enviar `X-Company-Id` y prellenar `companyId` con ese mismo valor; no lo muestres como campo editable cuando ya hay contexto.

Campos recomendados para formularios:

- Clave: `key`.
- Nombre: `name`.
- Subcuenta Cardcloud: `cardcloudSubaccountId`, siempre solo lectura. Lo genera backend al crear la subcuenta en Cardcloud.
- Predeterminada: `isDefault`, checkbox. Si se marca, mueve la predeterminada de la compania a esa subcompania.
- Estado: `status`, con `active` como valor inicial.
- Direccion: grupo colapsable u opcional basado en `address`.

En tablas, evita mostrar UUIDs. Usa `company.name`, `company.key`, `key` y `name`. Conserva `id` y `companyId` solo para acciones, filtros y payloads.

No permitas editar `key` ni `cardcloudSubaccountId` desde el formulario. Si se necesita corregir esa relacion, debe hacerse como proceso operativo controlado.

Las acciones de descarga son botones secundarios de exportacion; no requieren pantalla CRUD propia. El front debe tratar la respuesta como archivo binario y usar el nombre recibido en `Content-Disposition`.

## Errores comunes

| Estado | Caso                                                       |
| ------ | ---------------------------------------------------------- |
| `400`  | Datos relacionados no validos o parametros invalidos.      |
| `401`  | Request sin autenticacion valida.                          |
| `403`  | Usuario autenticado sin el permiso requerido.              |
| `404`  | Sub-compania no encontrada.                                |
| `409`  | Conflictos de unicidad segun constraints Prisma.           |
| `502`  | No se pudo completar la operacion con el servicio externo. |
