## Base

Base path: `/api/cardholders`

Este modulo es una vista independiente de tarjetahabientes, fuera de Administracion. No debe confundirse con `/api/cardholder`, que es el portal propio del tarjetahabiente autenticado.

## Alcance por compania

Requiere header `X-Company-Id: <companyId>`. El listado queda limitado a usuarios con acceso `cardholder.*` dentro de esa compania. Si el usuario autenticado tiene alcance `scopeKey: "subCompanyId"`, solo ve tarjetahabientes de sus subcompanias permitidas.

## Endpoints

| Metodo | Ruta                      | Permiso                 | Descripcion                                |
| ------ | ------------------------- | ----------------------- | ------------------------------------------ |
| `GET`  | `/api/cardholders`        | `cardholders.read-list` | Lista usuarios con perfil tarjetahabiente. |
| `GET`  | `/api/cardholders/export` | `cardholders.read-list` | Exporta tarjetahabientes filtrados.        |

## Listar tarjetahabientes

`GET /api/cardholders`

Query params:

| Campo          | Tipo      | Requerido | Descripcion                                                                           |
| -------------- | --------- | --------- | ------------------------------------------------------------------------------------- |
| `page`         | `number`  | No        | Pagina. Default `1`.                                                                  |
| `limit`        | `number`  | No        | Registros por pagina. Maximo `100`.                                                   |
| `search`       | `string`  | No        | Busca por usuario, correo, nombre, conductor, subcompania, vehiculo, tarjeta o stock. |
| `all`          | `boolean` | No        | Si es `true`, ignora `page` y `limit`, no pagina y devuelve todos los registros filtrados. |
| `status`       | `Status`  | No        | Filtra por estatus del usuario.                                                       |
| `subCompanyId` | `uuid`    | No        | Filtra tarjetahabientes con acceso a una subcompania especifica.                      |
| `hasDriver`    | `boolean` | No        | `true` solo vinculados a conductor; `false` solo sin conductor visible.               |
| `hasCards`     | `boolean` | No        | `true` solo con tarjetas vinculadas; `false` solo sin tarjetas visibles.              |

## Exportar tarjetahabientes

`GET /api/cardholders/export`

Requiere `cardholders.read-list`.

Query params: acepta los mismos filtros de `GET /api/cardholders` mas `format`.

`format`: `xlsx`, `excel`, `csv`, `txt` o `pdf`. Default `xlsx`.

Response `200`: archivo descargable. El backend aplica filtros y alcance igual que el listado, ignora paginacion y limita la exportacion a `5000` filas. No exporta datos sensibles de tarjetas ni credenciales.

## Reglas

- El endpoint lista usuarios con accesos cuyo rol tenga permisos `cardholder.*`.
- `isOperational` es `true` solo cuando el usuario tiene conductor visible, al menos un vehiculo visible y al menos una tarjeta visible.
- Un usuario puede tener rol tarjetahabiente y aun no estar operativo si falta vincular `Driver.userId`, vehiculo o tarjeta.
- No retorna datos sensibles de tarjeta, NIP, CVV, PAN completo, hashes ni tokens.

## Notas para frontend

No conectes este endpoint a una entrada de sidebar por defecto. El sidebar actual del tarjetahabiente se divide en `Tarjetas`, `Vehiculos` y `Trabajo`; esas rutas consumen `/api/cardholder/*` y se controlan con `cardholderCards`, `cardholderVehicles` y `cardholderWork`.

Usa `/api/cardholders` solo si producto pide una vista operativa para revisar altas incompletas de usuarios con perfil tarjetahabiente. En ese caso, la entrada de ruta debe usar `modules.cardholders.canEnter` y sus acciones internas deben salir de `modules.cardholders.actions`; no reutilices las capabilities del portal propio del tarjetahabiente.

Capabilities esperadas:

| Elemento frontend      | Capability                                         | Permiso base              |
| ---------------------- | -------------------------------------------------- | ------------------------- |
| Ruta operativa         | `modules.cardholders.canEnter`                     | `cardholders.module`      |
| Listado                | `modules.cardholders.actions.readList`             | `cardholders.read-list`   |
| Recargar listado       | `modules.cardholders.actions.refreshList`          | `cardholders.read-list`   |
| Configurar columnas    | `modules.cardholders.actions.configureColumns`     | `cardholders.read-list`   |
| Exportar listado       | `modules.cardholders.actions.exportList`           | `cardholders.read-list`   |
| Filtro por subcompania | `modules.cardholders.actions.openSubCompanyFilter` | `sub-companies.read-list` |
| Filtro de pendientes   | `modules.cardholders.actions.filterPendingSetup`   | `cardholders.read-list`   |
| Detalle                | `modules.cardholders.actions.openDetail`           | `cardholders.read-list`   |
| Drawer de detalle      | `modules.cardholders.actions.openDetailDrawer`     | `cardholders.read-list`   |

Campos visibles recomendados:

- Usuario: `fullName`, `email`, `status`.
- Conductor: `driver.name`.
- Subcompania: `driver.subCompany.name` o `driver.subCompany.key`.
- Operativo: derivar de `isOperational`.
- Vehiculos: `counts.vehicles`.
- Tarjetas: `counts.cards`.

Filtros recomendados:

- Busqueda libre con `search`.
- Subcompania con `subCompanyId`.
- Pendientes de configurar con `hasDriver=false` o `hasCards=false`.

No muestres `scopeKey`, `scopeId`, `companyId` ni `cardcloudSubaccountId` como campos editables. Son datos tecnicos para relacionar accesos y subcuentas.

`exportList` usa `GET /api/cardholders/export`; `configureColumns` sigue siendo accion local de interfaz.
