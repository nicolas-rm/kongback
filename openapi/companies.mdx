## Base

Base path: `/api/companies`

Todos los endpoints requieren autenticacion y permisos `companies.*`. El borrado desactiva el registro cambiando `status` a `inactive`.

## Alcance

`Company` es el tenant/cliente operativo. `GET /api/companies` devuelve las companias accesibles para el usuario actual. Un admin global ve todas; un usuario con accesos por compania ve solo las asignadas.

Crear, actualizar y desactivar companias requiere acceso global. `X-Company-Id` no se usa en este modulo; la seleccion de compania aplica a los modulos operativos dependientes.

## Modelo

```json
{
    "id": "0ed7e7e1-2b6d-45cf-94c7-79bf03bbaf02",
    "key": "COMPANY001",
    "externalId": "EXT-001",
    "name": "Acme Logistics",
    "tradeName": "Acme",
    "status": "active",
    "address": {
        "street": "Main St",
        "exteriorNumber": "100",
        "interiorNumber": null,
        "neighborhood": "Centro",
        "municipality": "Monterrey",
        "city": "Monterrey",
        "state": "Nuevo Leon",
        "country": "MX",
        "postalCode": "64000",
        "references": null
    }
}
```

`status`: `active`, `inactive`, `suspended`.

En listados, `address` no se devuelve para mantener el payload liviano. `address` si aparece en detalle, create y update.

## Endpoints

| Metodo   | Ruta                 | Permiso               | Descripcion             |
| -------- | -------------------- | --------------------- | ----------------------- |
| `POST`   | `/api/companies`     | `companies.create`    | Crea una compania.      |
| `GET`    | `/api/companies`     | `companies.read-list` | Lista companias.        |
| `GET`    | `/api/companies/:id` | `companies.read-one`  | Obtiene una compania.   |
| `PATCH`  | `/api/companies/:id` | `companies.update`    | Actualiza una compania. |
| `DELETE` | `/api/companies/:id` | `companies.delete`    | Desactiva una compania. |

## Listado

`GET /api/companies`

Query params: `page`, `limit`, `search`, `all`, `status`.

`search` busca por `key`, `externalId`, `name` y `tradeName`.

```http
GET /api/companies?page=1&limit=20&search=acme&status=active
```

Response `200`: resultado paginado de `Company` sin `address`.

## Crear

`POST /api/companies`

```json
{
    "key": "COMPANY001",
    "externalId": "EXT-001",
    "name": "Acme Logistics",
    "tradeName": "Acme",
    "status": "active",
    "address": {
        "street": "Main St",
        "city": "Monterrey",
        "state": "Nuevo Leon",
        "country": "MX",
        "postalCode": "64000"
    }
}
```

Requeridos: `key`, `name`.

Opcionales: `externalId`, `tradeName`, `status`, `address`. Strings vacios opcionales se transforman a `null`.

Requiere acceso global. No requiere `X-Company-Id`.

Al crear, el backend primero crea una subcuenta en Cardcloud con `ExternalId = key` y `Description = tradeName ?? name`. Si Cardcloud falla o no devuelve un identificador valido, no se crea la compania local. Con el identificador devuelto se crea tambien una subcompania principal (`isDefault: true`) ligada por `cardcloudSubaccountId`.

Response `201`:

## Obtener

`GET /api/companies/:id`

Path params: `id` UUID de la compania.

Response `200`: `Company` con `address`.

## Actualizar

`PATCH /api/companies/:id`

Acepta `externalId`, `name`, `tradeName`, `status` y `address`, todos opcionales. `key` no es editable porque se usa como referencia externa de la subcuenta Cardcloud principal.

Response `200`: `Company` actualizada con `address`.

## Desactivar

`DELETE /api/companies/:id`

Response `200`:

```json
{
    "id": "0ed7e7e1-2b6d-45cf-94c7-79bf03bbaf02",
    "status": "inactive"
}
```

## Notas para frontend

Este modulo tambien aplica las reglas CRUD de `Frontend Guidelines`: crear con campos visibles/derivados, editar solo campos documentados en `Actualizar`, confirmar desactivacion y refrescar el listado despues de cada mutacion.

Este modulo administra clientes/tenants. No debe depender de la compania seleccionada y no debe enviar `X-Company-Id`.

No generes un modulo separado de `workspaces`. En este proyecto, la compania es el tenant/cliente operativo. El selector de contexto del usuario debe mostrar companias accesibles, no workspaces independientes.

Campos recomendados para formularios:

- Clave: `key`.
- Nombre legal: `name`.
- Nombre comercial: `tradeName`.
- Estado: `status`, con `active` como valor inicial.
- Direccion: grupo colapsable u opcional basado en `address`.

Campos que pueden omitirse si el negocio no los usa en pantalla:

- `externalId`: mostrar como `ID externo` solo si hay integracion o migracion que lo requiera.
- `address`: no pedirlo en alta rapida; puede capturarse despues desde editar.

No permitas editar `key` despues de crear. Si se requiere corregir una clave, debe manejarse como proceso operativo porque existe una subcuenta Cardcloud ligada.

Para selector de compania del usuario autenticado, usa `GET /api/authentication/companies`. Usa `GET /api/companies` para administracion/catalogo de companias.

## Errores comunes

| Estado | Caso                                                                                        |
| ------ | ------------------------------------------------------------------------------------------- |
| `400`  | Body, query o path params invalidos.                                                        |
| `401`  | Request sin autenticacion valida.                                                           |
| `403`  | Usuario autenticado sin el permiso requerido o sin alcance suficiente para crear companias. |
| `404`  | Compania no encontrada.                                                                     |
| `409`  | Conflictos de unicidad segun constraints Prisma.                                            |
| `502`  | No se pudo completar la operacion con el servicio externo.                                  |
