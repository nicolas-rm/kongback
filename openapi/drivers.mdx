## Base

Base path: `/api/drivers`

Todos los endpoints requieren autenticacion y permisos `drivers.*`. El borrado desactiva el registro cambiando `status` a `inactive`.

## Alcance por compania

Requiere header `X-Company-Id: <companyId>`. Todas las operaciones quedan limitadas a esa compania. Si el acceso del usuario tiene `scopeKey: "subCompanyId"`, `subCompanyId`, el conductor consultado y sus relaciones tambien deben pertenecer a una de esas subcompanias.

## Endpoints

| Metodo   | Ruta                        | Permiso                      | Descripcion                             |
| -------- | --------------------------- | ---------------------------- | --------------------------------------- |
| `POST`   | `/api/drivers`              | `drivers.create`             | Crea un conductor.                      |
| `GET`    | `/api/drivers`              | `drivers.read-list`          | Lista conductores.                      |
| `GET`    | `/api/drivers/:id/vehicles` | `drivers.vehicles.read-list` | Lista vehiculos asignados al conductor. |
| `GET`    | `/api/drivers/:id`          | `drivers.read-one`           | Obtiene un conductor.                   |
| `PATCH`  | `/api/drivers/:id`          | `drivers.update`             | Actualiza un conductor.                 |
| `DELETE` | `/api/drivers/:id`          | `drivers.delete`             | Desactiva un conductor.                 |

## Listado

`GET /api/drivers`

Query params: `page`, `limit`, `search`, `all`, `status`, `subCompanyId`, `userId`.

`search` busca por `name`, `externalReference`, `subCompany.key`, `subCompany.name`, `user.username` y `user.fullName`.

Para columnas relacionadas, usa `subCompany.name` y `user.fullName`; conserva `subCompanyId` y `userId` para acciones y formularios.

Response `200`: resultado paginado de `Driver` con `subCompany` y `user` summaries, sin `address`.

## Crear

`POST /api/drivers`

```json
{
    "subCompanyId": "79d03f1d-3da4-478e-806e-75ef9d86c992",
    "userId": "9f5f0f4a-8f88-4f0b-9a18-6eb3f1e9b7a1",
    "name": "Maria Garcia",
    "externalReference": "DRV-001",
    "status": "active"
}
```

Requeridos: `subCompanyId`, `name`. `subCompanyId` debe estar activo y pertenecer a la compania enviada en `X-Company-Id`.

Opcionales: `userId`, `externalReference`, `status`, `address`. Si `userId` se envia, debe ser un usuario activo.

Response `201`: `Driver` con `subCompany`, `user` y `address`.

## Obtener

`GET /api/drivers/:id`

Path params: `id` UUID del conductor.

Response `200`: `Driver` con `subCompany`, `user` y `address`.

## Vehiculos del conductor

`GET /api/drivers/:id/vehicles`

Permiso: `drivers.vehicles.read-list`.

Query params: `page`, `limit`, `search`, `all`, `status`.

`search` busca por `plates`, `economicNumber`, `model`, `subCompany.key`, `subCompany.name`, `fuel.code`, `fuel.name` y `driver.name`.

Response `200`: resultado paginado de `Vehicle` con `subCompany`, `fuel` y `driver` summaries.

Nota: el modelo actual guarda solo la relacion vigente `vehicle.driverId`; este endpoint no devuelve historial de asignaciones anteriores.

## Actualizar

`PATCH /api/drivers/:id`

Acepta `userId`, `name`, `externalReference`, `status` y `address`, todos opcionales. `userId` puede enviarse como `null` para desvincular.

Response `200`: `Driver` actualizado con `subCompany`, `user` y `address`.

## Desactivar

`DELETE /api/drivers/:id`

Response `200`:

```json
{
    "id": "d77d1344-93d4-4dc2-923a-b241185692de",
    "status": "inactive"
}
```

## Notas para frontend

Este modulo tambien aplica las reglas CRUD de `Frontend Guidelines`: crear con campos visibles/derivados, editar solo campos documentados en `Actualizar`, confirmar desactivacion y refrescar el listado despues de cada mutacion.

### Capabilities para UI

Usa `GET /api/authentication/capabilities` para decidir entrada al menu y acciones visibles:

- Menu `Conductores`: `sidebar.drivers.canEnter`.
- Pantalla `Conductores`: `modules.drivers.canEnter`.
- Crear conductor: `modules.drivers.actions.openCreate` y `modules.drivers.actions.create`.
- Pestañas de crear `Formulario` y `Direccion`: `modules.drivers.actions.openCreateForm` y `modules.drivers.actions.openCreateAddress`.
- Selector `Subcompania`: `modules.drivers.actions.openSubCompanySelect`.
- Selector `Usuario vinculado`: `modules.drivers.actions.openLinkedUserSelect`.
- Consultar listado: `modules.drivers.actions.readList`.
- Refrescar listado: `modules.drivers.actions.refreshList`.
- Configurar columnas: `modules.drivers.actions.configureColumns`.
- Exportar listado desde el front: `modules.drivers.actions.exportList`.
- Abrir detalle: `modules.drivers.actions.openDetail` u `modules.drivers.actions.openDetailDrawer`.
- Consultar detalle: `modules.drivers.actions.readOne`.
- Pestañas de detalle `Formulario` y `Direccion`: `modules.drivers.actions.openDetailForm` y `modules.drivers.actions.openDetailAddress`.
- Editar conductor: `modules.drivers.actions.openEdit` u `modules.drivers.actions.openEditDrawer`.
- Pestañas de editar `Formulario` y `Direccion`: `modules.drivers.actions.openEditForm` y `modules.drivers.actions.openEditAddress`.
- Actualizar conductor: `modules.drivers.actions.update`.
- Desactivar conductor: `modules.drivers.actions.openDeactivate`, `modules.drivers.actions.openDeactivateDialog` o `modules.drivers.actions.deactivate`.
- Abrir drawer `Vehiculos del conductor`: `modules.drivers.actions.openVehicles` u `modules.drivers.actions.openVehiclesDrawer`.
- Consultar vehiculos del conductor: `modules.drivers.actions.readVehicles`.
- Buscar vehiculos del conductor: `modules.drivers.actions.searchVehicles`.
- Exportar vehiculos desde el front: `modules.drivers.actions.exportVehicles`.

`configureColumns`, `exportList` y `exportVehicles` no representan endpoints dedicados; son acciones de interfaz permitidas cuando el usuario puede consultar los datos correspondientes. `delete` en este modulo significa desactivar el conductor, no borrado fisico. El selector de subcompania requiere permiso de lectura de subcompanias y el selector de usuario vinculado requiere permiso de lectura de usuarios.

El front debe enviar `X-Company-Id` y poblar `subCompanyId` desde un select de subcompanias disponibles para la compania seleccionada. Si el usuario autenticado esta limitado a subcompanias, ese select solo debe contener las que devuelve el backend.

Campos recomendados para formularios:

- Subcompania: `subCompanyId`.
- Nombre: `name`.
- Usuario vinculado: `userId`, opcional; mostrar `user.fullName` en tablas.
- Referencia externa: `externalReference`, opcional.
- Estado: `status`, con `active` como valor inicial.
- Direccion: grupo opcional basado en `address`.

No muestres `userId` ni `subCompanyId` como texto libre. Deben ser selects. Para desvincular usuario en editar, envia `userId: null`.

Para tarjetahabientes, `userId` es la relacion que habilita `/api/cardholder/*`. El usuario debe tener rol/permisos `cardholder.*` y el conductor debe estar activo en la misma subcompania usada como alcance del acceso del usuario. Si el conductor se desactiva o se desvincula con `userId: null`, el usuario ya no podra entrar al modulo propio de tarjetahabiente.

Para consultar vehiculos relacionados desde el detalle del conductor usa `GET /api/drivers/:id/vehicles`. No lo uses como historial; hoy representa la asignacion actual.

## Errores comunes

| Estado | Caso                                                  |
| ------ | ----------------------------------------------------- |
| `400`  | Datos relacionados no validos o parametros invalidos. |
| `401`  | Request sin autenticacion valida.                     |
| `403`  | Usuario autenticado sin el permiso requerido.         |
| `404`  | Conductor no encontrado.                              |
| `409`  | Conflictos de unicidad segun constraints Prisma.      |
