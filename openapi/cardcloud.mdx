# Cardcloud

Base path: `/api/cardcloud`

Este modulo concentra endpoints proxy hacia la API externa de Cardcloud. Las rutas de espejo local, sincronizacion y asignacion de stock a subcompania/subcuenta viven en `cardcloud-stock`.

Convenciones de contrato:

- Las respuestas marcadas como "respuesta cruda de Cardcloud" se reenvian desde el proveedor sin transformar su estructura de negocio.
- Los contratos TypeScript de respuestas Cardcloud viven en `src/modules/cardcloud/types/cardcloud-provider.types.ts`.
- Las respuestas de cuenta, tarjetas, subcuentas, fondeo, fondeo masivo, fondeo por Excel, stock y sync tienen tipos internos del backend. Si Cardcloud cambia su payload, primero ajusta esos tipos y despues esta documentacion.
- Los endpoints con alcance `Sistema/compania` son mixtos: sin `X-Company-Id` requieren acceso global; con `X-Company-Id` validan compania, permisos y, si aplica, subcompanias visibles.
- `sourceType` y `destinationType` aceptan solo `account`, `subaccount` o `card`.

## Cuenta

`GET /api/cardcloud/account`

Requiere `RequireSystemAccess` y permiso `cardcloud.account.read-one`.

Response `200`: `CardcloudAccountResponse`.

```json
{
    "account": "ACCOUNT-ID",
    "wallet": {
        "wallet_id": "WALLET-ID",
        "balance": "1000.00",
        "clabe": "000000000000000000",
        "last_movements": [
            {
                "movement_id": "MOVEMENT-ID",
                "card": {
                    "card_id": "CARD-ID",
                    "masked_pan": "XXXXXXXXXXXX1234"
                },
                "type": "transfer",
                "description": "Carga inicial",
                "reference": "REF-001",
                "amount": "100.00",
                "balance": "1000.00",
                "date": "1720000000"
            }
        ]
    }
}
```

Uso frontend: alimenta la pestana `Cuenta` de `/cardcloud/account` y el boton `Recargar`. Muestra informacion de cuenta conectada, wallet y saldo.

`GET /api/cardcloud/account/movements`

Requiere `RequireSystemAccess` y permiso `cardcloud.account.movements.read-list`.

Query params opcionales:

| Campo  | Tipo     | Descripcion                       |
| ------ | -------- | --------------------------------- |
| `from` | `string` | Timestamp Unix inicial, segundos. |
| `to`   | `string` | Timestamp Unix final, segundos.   |

Response `200`: `CardcloudAccountMovementsResponse` con `movements[]`.

Uso frontend: alimenta la pestana `Movimientos` de `/cardcloud/account`. El boton `Consultar` debe llamar este endpoint con `from` y `to` cuando existan filtros. El boton `Limpiar` es accion local de UI: limpia fechas y vuelve al rango default que defina el producto, no requiere endpoint dedicado.

`GET /api/cardcloud/account/movements/export`

Requiere `RequireSystemAccess` y permiso `cardcloud.account.movements.read-list`.

Query params opcionales: `from`, `to`, `format`.

Response `200`: archivo descargable. `format` acepta `xlsx`, `excel`, `csv`, `txt` o `pdf`; default `xlsx`. Exporta hasta `5000` movimientos de cuenta devueltos por Cardcloud para el rango consultado.

## Transferencias

`POST /api/cardcloud/account/transfer`

Requiere `RequireSystemAccess` y permiso `cardcloud.account.transfer`.

Body:

| Campo             | Tipo                            | Requerido | Descripcion                          |
| ----------------- | ------------------------------- | --------- | ------------------------------------ |
| `sourceType`      | `account \| subaccount \| card` | Si        | Origen.                              |
| `source`          | `string`                        | Si        | ID externo origen.                   |
| `destinationType` | `account \| subaccount \| card` | Si        | Destino.                             |
| `destination`     | `string`                        | Si        | ID externo destino.                  |
| `amount`          | `number`                        | Si        | Monto; valor absoluto minimo `0.01`. |
| `description`     | `string`                        | Si        | Descripcion.                         |

Si `amount` es negativo, backend invierte origen/destino y envia el monto absoluto a Cardcloud, igual que BackendGas. Cuando la operacion se procesa desde un usuario autenticado, se crea una notificacion propia de exito.

Response `200`: `CardcloudTransferFundsResponse` con `new_balance` y `movement`.

`POST /api/cardcloud/account/transfer-bulk`

Requiere `RequireSystemAccess` y permiso `cardcloud.account.transfer.bulk`.

Body:

```json
{
    "transfers": [
        {
            "sourceType": "account",
            "source": "ACCOUNT-ID",
            "destinationType": "card",
            "destination": "CARD-ID",
            "amount": 100,
            "description": "Carga inicial"
        }
    ]
}
```

Reglas:

- `transfers` requiere de `1` a `50` elementos.
- Cada elemento usa el mismo contrato de `POST /api/cardcloud/account/transfer`.
- El backend continua procesando los demas elementos aunque una transferencia falle.
- Al terminar, se crea una notificacion propia de exito o advertencia para el usuario que ejecuto la accion.

Response `200`:

```json
{
    "results": [
        {
            "index": 0,
            "success": true,
            "data": {}
        }
    ],
    "summary": {
        "total": 1,
        "succeeded": 1,
        "failed": 0
    }
}
```

| Campo               | Tipo                             | Descripcion                                |
| ------------------- | -------------------------------- | ------------------------------------------ |
| `results[].index`   | `number`                         | Posicion original dentro de `transfers`.   |
| `results[].success` | `boolean`                        | Indica si esa transferencia se ejecuto.    |
| `results[].data`    | `CardcloudTransferFundsResponse` | Respuesta de Cardcloud cuando fue exitosa. |
| `results[].error`   | `string`                         | Mensaje de error cuando fallo.             |
| `summary.total`     | `number`                         | Total de transferencias solicitadas.       |
| `summary.succeeded` | `number`                         | Transferencias exitosas.                   |
| `summary.failed`    | `number`                         | Transferencias fallidas.                   |

`GET /api/cardcloud/account/transfer-bulk-excel`

Requiere `RequireSystemAccess` y permiso `cardcloud.account.transfer.bulk`.

Query params:

| Campo          | Tipo     | Requerido | Descripcion                                                                       |
| -------------- | -------- | --------- | --------------------------------------------------------------------------------- |
| `subCompanyId` | `string` | No        | Si se envia, precarga la plantilla con `clientId` de tarjetas de esa subcompania. |

Response `200`: `CardcloudTransferBulkExcelTemplateResponse` entregado como archivo `.xlsx` con hoja `Fondeo` y columnas `clientId`, `monto`, `description`, mas una hoja `Instrucciones`.

`POST /api/cardcloud/account/transfer-bulk-excel`

Requiere `RequireSystemAccess` y permiso `cardcloud.account.transfer.bulk`.

Content-Type: `multipart/form-data`.

Campos:

| Campo          | Tipo     | Requerido | Descripcion                                                  |
| -------------- | -------- | --------- | ------------------------------------------------------------ |
| `subCompanyId` | `string` | Si        | Subcompania local origen del fondeo.                         |
| `file`         | `file`   | Si        | Archivo `.xlsx`; columnas obligatorias `clientId` y `monto`. |

Reglas:

- El backend resuelve `source = subCompany.cardcloudSubaccountId`.
- `description` es columna opcional. Si falta o viene vacia, el backend genera una descripcion default por fila.
- Tambien se aceptan encabezados equivalentes: `client_id`, `client id`, `clienteId`, `importe`, `descripcion`, `concepto` y `detalle`.
- Cada fila procesable debe tener `clientId` y `monto`. Las filas vacias o incompletas se omiten con estado `omitted`.
- Cada `clientId` procesable debe corresponder a una tarjeta activa de esa subcompania.
- `monto` acepta valores positivos y negativos. Si es negativo, el backend invierte origen/destino antes de llamar Cardcloud.
- Se procesan lotes de hasta 50 transferencias y se devuelve resultado por fila.
- Al terminar, se crea una notificacion propia de exito o advertencia para el usuario que ejecuto la accion.

Response `200`:

```json
{
    "subCompanyId": "019cd4ad-38dd-7125-a68a-209519d79869",
    "results": [
        {
            "row": 2,
            "clientId": "CLI-001",
            "amount": 100,
            "description": "Carga semanal",
            "status": "succeeded",
            "newBalance": "250.00",
            "message": "Transferencia procesada correctamente."
        }
    ],
    "summary": {
        "totalRows": 1,
        "prepared": 1,
        "succeeded": 1,
        "failed": 0,
        "omitted": 0
    }
}
```

| Campo                   | Tipo                             | Descripcion                                      |
| ----------------------- | -------------------------------- | ------------------------------------------------ |
| `subCompanyId`          | `string`                         | UUID local de la subcompania procesada.          |
| `results[].row`         | `number`                         | Numero de fila en el Excel.                      |
| `results[].clientId`    | `string \| null`                 | Client ID leido de la fila.                      |
| `results[].amount`      | `number \| null`                 | Monto parseado de la fila.                       |
| `results[].description` | `string \| null`                 | Descripcion leida del Excel; puede ser `null`.   |
| `results[].status`      | `succeeded \| failed \| omitted` | Resultado por fila.                              |
| `results[].newBalance`  | `string \| null`                 | Nuevo balance si Cardcloud lo devuelve.          |
| `results[].message`     | `string`                         | Mensaje operativo para mostrar al usuario.       |
| `summary.totalRows`     | `number`                         | Filas leidas del archivo despues del encabezado. |
| `summary.prepared`      | `number`                         | Filas validas enviadas a Cardcloud.              |
| `summary.succeeded`     | `number`                         | Filas procesadas correctamente.                  |
| `summary.failed`        | `number`                         | Filas fallidas.                                  |
| `summary.omitted`       | `number`                         | Filas omitidas por estar vacias o incompletas.   |

Errores `400` frecuentes:

- Falta `file`.
- Archivo vacio.
- Extension distinta de `.xlsx`.
- MIME distinto de Excel permitido.
- Excel ilegible, sin hojas, sin columna `clientId` o sin columna `monto`.
- Monto con valor absoluto menor a `0.01`.

## Asignacion de tarjetas

Estos endpoints son proxy tecnico a Cardcloud y reciben `subaccount_id` externo. Para el flujo normal de asignar tarjetas a una subcompania local, usa `POST /api/cards/assign-sub-company`; ese endpoint resuelve `subaccount_id` desde `subCompany.cardcloudSubaccountId`. Para asignacion masiva por archivo, usa `GET /api/cards/assign-sub-company-excel` y `POST /api/cards/assign-sub-company-excel`; ese flujo procesa `clientId` del Excel y resuelve internamente la tarjeta externa.

`POST /api/cardcloud/account/cards/assign`

Requiere `RequireSystemAccess` y permiso `cardcloud.cards.assign`.

Body:

| Campo           | Tipo     | Requerido |
| --------------- | -------- | --------- |
| `subaccount_id` | `string` | Si        |
| `card_type`     | `string` | Si        |
| `quantity`      | `number` | Si        |

Response `200`: `CardcloudAssignCardsResponse` con `cards[]`, `page`, `total_pages` y `total_records`.

`POST /api/cardcloud/account/cards/assign-bulk`

Requiere `RequireSystemAccess` y permiso `cardcloud.cards.assign.bulk`.

Body:

| Campo           | Tipo       | Requerido |

| `subaccount_id` | `string`   | Si        |
| `cards`         | `string[]` | Si        |

Response `200`: `CardcloudAssignCardsResponse` con `cards[]`, `page`, `total_pages` y `total_records`.

## Subcuentas

`GET /api/cardcloud/subaccounts`

Sin `X-Company-Id`, requiere acceso sistema y responde como proxy global de Cardcloud.

Con `X-Company-Id`, devuelve solo las subcuentas externas que estan vinculadas a subcompanias locales activas de esa compania mediante `SubCompany.cardcloudSubaccountId`. Si el usuario esta limitado a subcompanias, tambien se restringe a esas subcompanias. En ese modo cada subcuenta encontrada se enriquece con `localSubCompany`.

Response `200`: `CardcloudSubaccountsResponse`; con contexto de compania responde `CardcloudVisibleSubaccountsResponse`, filtrado por subcuentas vinculadas localmente.

Ejemplo con `X-Company-Id`:

```json
{
    "subaccounts": [
        {
            "subaccount_id": "cardcloud-subaccount-id",
            "external_id": "COMPANY__SUB",
            "description": "Subcompania Operativa",
            "wallet": {
                "wallet_id": "WALLET-ID",
                "balance": "500.00",
                "clabe": "000000000000000000",
                "last_movements": []
            },
            "localSubCompany": {
                "id": "019d6f62-9559-7ab5-9e1d-41ee8953f62b",
                "key": "SUB",
                "name": "Subcompania Operativa",
                "companyId": "019d6f62-9775-7b89-8e2e-8bf81a8d64f1"
            }
        }
    ]
}
```

`GET /api/cardcloud/subaccounts/export`

Requiere `RequireSystemOrCompanyAccess` y permiso `cardcloud.subaccounts.read-list`.

Query params:

| Campo    | Tipo                         | Requerido | Descripcion                                                    |
| -------- | ---------------------------- | --------- | -------------------------------------------------------------- |
| `format` | `xlsx \| excel \| csv \| txt \| pdf` | No        | Formato de salida. Default `xlsx`; `excel` es alias de `xlsx`. |

Response `200`: archivo descargable. Sin `X-Company-Id` exporta las subcuentas que devuelve Cardcloud; con `X-Company-Id` exporta solo subcuentas vinculadas a subcompanias locales visibles. Limite operativo: `5000` filas.

Response `200`: `CardcloudSubaccountDetail`.

`GET /api/cardcloud/subaccounts/:uuid/cards`

Sin `X-Company-Id`, requiere acceso sistema. Con `X-Company-Id`, valida que `uuid` pertenezca a una subcompania local activa y visible para el usuario.

Query params opcionales:

| Campo  | Tipo     | Descripcion |
| ------ | -------- | ----------- |
| `page` | `string` | Pagina.     |

Response `200`: `CardcloudSubaccountCardsResponse`.

`GET /api/cardcloud/subaccounts/:uuid/cards/export`

Sin `X-Company-Id`, requiere acceso sistema. Con `X-Company-Id`, valida que `uuid` pertenezca a una subcompania local activa y visible para el usuario.

Query params opcionales: `page`, `format`.

Response `200`: archivo descargable. `format` acepta `xlsx`, `excel`, `csv`, `txt` o `pdf`; default `xlsx`. Exporta hasta `5000` tarjetas de la pagina de subcuenta devuelta por Cardcloud.

Body:

`GET /api/cardcloud/subaccounts/:uuid/movements`

## Reglas y seguridad

- `CardcloudExternalService` es el unico servicio que se conecta a la API externa.
- `CardcloudService` coordina proxy externo, normalizacion de transferencias y utilidades compartidas con `cardcloud-stock`.
- Los endpoints de subcuentas Cardcloud son mixtos para lectura: sin `X-Company-Id` operan como proxy global; con `X-Company-Id` solo exponen subcuentas externas relacionadas con subcompanias locales activas de esa compania.
- Las mutaciones y operaciones criticas de Cardcloud siguen requiriendo acceso global de sistema.
- El espejo local de stock, su sincronizacion y asignacion a subcompania/subcuenta se administran en `/api/cardcloud-stock`.
- No filtres datos sensibles solo en frontend. Los endpoints `sensitive`, `cvv` y `nip` deben mostrarse solo bajo accion explicita, con confirmacion, y nunca persistirse ni loguearse en frontend.

## Notas para frontend

No generes una pagina CRUD nueva por cada endpoint de Cardcloud. Los endpoints externos son acciones tecnicas del proveedor y deben exponerse solo como herramientas puntuales para usuarios globales autorizados.

### Capabilities para UI: Cuenta Cardcloud

Usa `GET /api/authentication/capabilities` para decidir entrada al menu y acciones visibles:

- Menu `Cuenta`: `sidebar.cardcloudAccount.canEnter`.
- Pantalla `Cuenta Cardcloud`: `modules.cardcloudAccount.canEnter`.
- Pestana `Cuenta`: `modules.cardcloudAccount.actions.openAccountTab` y `modules.cardcloudAccount.actions.readOne`.
- Boton `Recargar`: `modules.cardcloudAccount.actions.refreshAccount`.
- Pestana `Movimientos`: `modules.cardcloudAccount.actions.openMovementsTab` y `modules.cardcloudAccount.actions.readMovements`.
- Filtros `Desde` y `Hasta`: `modules.cardcloudAccount.actions.filterMovements`.
- Boton `Limpiar`: `modules.cardcloudAccount.actions.clearMovementFilters`.
- Boton `Consultar`: `modules.cardcloudAccount.actions.consultMovements`.
- Boton `Exportar movimientos`: `modules.cardcloudAccount.actions.exportMovements`.

`refreshAccount`, `openAccountTab` y `readOne` usan `cardcloud.account.read-one`. `openMovementsTab`, `readMovements`, `filterMovements`, `clearMovementFilters`, `consultMovements` y `exportMovements` usan `cardcloud.account.movements.read-list`. `exportMovements` descarga `GET /api/cardcloud/account/movements/export`.

Esta pantalla no debe mostrar acciones de transferencia. Las transferencias se exponen como accion contextual de Fondeos dentro de Subcompanias y usan `cardcloud.account.transfer` o `cardcloud.account.transfer.bulk`.

### Capabilities para UI: Transferencias Cardcloud

Usa `GET /api/authentication/capabilities` para decidir entrada al menu y acciones visibles:

- No generes menu ni pantalla principal para `cardcloudTransfers`.
- Transferencia individual: `modules.cardcloudTransfers.actions.transfer`.
- Transferencia masiva: `modules.cardcloudTransfers.actions.transferBulk`.
- Descargar template de carga masiva: `modules.cardcloudTransfers.actions.downloadTemplate`.
- Cargar Excel de transferencias: `modules.cardcloudTransfers.actions.uploadExcel`.

Estas acciones se muestran dentro de otra pantalla, por ejemplo en el detalle de una subcompania, y siguen perteneciendo a `modules.cardcloudTransfers.actions`. La pantalla contenedora solo aporta contexto, como `subCompanyId`.

### Capabilities para UI: Subcuentas Cardcloud

Usa `GET /api/authentication/capabilities` para decidir entrada al menu y acciones visibles:

- Menu `Subcuentas`: `sidebar.cardcloudSubaccounts.canEnter`.
- Pantalla `Subcuentas Cardcloud`: `modules.cardcloudSubaccounts.canEnter`.
- Consultar listado: `modules.cardcloudSubaccounts.actions.readList`.
- Refrescar listado: `modules.cardcloudSubaccounts.actions.refreshList`.
- Configurar columnas: `modules.cardcloudSubaccounts.actions.configureColumns`.
- Exportar listado: `modules.cardcloudSubaccounts.actions.exportList`.
- Abrir drawer de detalle: `modules.cardcloudSubaccounts.actions.openDetail` u `modules.cardcloudSubaccounts.actions.openDetailDrawer`.
- Pestaña `Detalle`: `modules.cardcloudSubaccounts.actions.openDetailTab` y `modules.cardcloudSubaccounts.actions.readOne`.
- Pestaña `Tarjetas`: `modules.cardcloudSubaccounts.actions.openCardsTab` y `modules.cardcloudSubaccounts.actions.readCards`.
- Buscar tarjetas de subcuenta: `modules.cardcloudSubaccounts.actions.searchCards`.
- Exportar tarjetas de subcuenta: `modules.cardcloudSubaccounts.actions.exportCards`.
- Pestaña `Movimientos`: `modules.cardcloudSubaccounts.actions.openMovementsTab` y `modules.cardcloudSubaccounts.actions.readMovements`.
- Filtrar movimientos por fecha: `modules.cardcloudSubaccounts.actions.filterMovements`.
- Limpiar filtros de movimientos: `modules.cardcloudSubaccounts.actions.clearMovementFilters`.
- Exportar movimientos de subcuenta: `modules.cardcloudSubaccounts.actions.exportMovements`.

`configureColumns` y `searchCards` son acciones locales de interfaz. `exportList` usa `GET /api/cardcloud/subaccounts/export`; `exportCards` usa `GET /api/cardcloud/subaccounts/:uuid/cards/export`; `exportMovements` usa `GET /api/cardcloud/subaccounts/:uuid/movements/export`. `searchCards` debe filtrar en frontend sobre las tarjetas ya cargadas de la subcuenta porque `GET /api/cardcloud/subaccounts/:uuid/cards` solo acepta `page`. Con `X-Company-Id`, el listado y detalle de subcuentas deben mostrar solo subcuentas Cardcloud cerradas contra subcompanias locales activas de la compania seleccionada.

Para asignar tarjetas Cardcloud a una subcompania operativa, usa `POST /api/cards/assign-sub-company` en lugar del proxy crudo `POST /api/cardcloud/account/cards/assign-bulk`. Para carga masiva por Excel, usa `GET /api/cards/assign-sub-company-excel` para plantilla precargada con `clientId` disponibles y `POST /api/cards/assign-sub-company-excel` con `multipart/form-data`.

Para mostrar o administrar el stock local sincronizado, usa la pagina `cardcloud-stock`.
