## Objetivo

Esta matriz documenta que permiso requiere cada endpoint HTTP del backend, que alcance aplica y por que ese permiso es necesario. La fuente de verdad son los decorators de los controllers:

- `@Public()`: endpoint publico; no requiere JWT.
- `@Permissions(...)`: permiso RBAC requerido por el `PermissionsGuard`.
- `@RequireSystemAccess()`: requiere acceso global de sistema (`companyId: null`).
- `@RequireCompany()`: requiere `X-Company-Id`; el guard valida compania activa y acceso del usuario.
- `@RequireSystemOrCompanyAccess()`: sin `X-Company-Id` opera con acceso global; con `X-Company-Id` opera dentro de la compania seleccionada.

Los endpoints sin `@Permissions(...)` pero no publicos siguen requiriendo JWT por el guard global de autenticacion. Se usan para flujos propios de sesion, perfil o seguridad donde el usuario solo opera sobre su cuenta.

Cuando un endpoint tiene `@Permissions(...)` pero no declara `@RequireSystemAccess()`, `@RequireCompany()` ni `@RequireSystemOrCompanyAccess()`, el `PermissionsGuard` valida el permiso RBAC con el contexto disponible. Si el request trae `X-Company-Id`, tambien valida la compania y resuelve `companyScope`; si no trae header, el permiso puede cumplirse con accesos activos globales o de compania segun el filtro de accesos.

## Resumen de cobertura

| Tipo de endpoint         | Criterio usado                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Publicos                 | Solo `@Public()`: raiz, health y flujos publicos de autenticacion.                                                     |
| Autenticados sin RBAC    | Flujos de cuenta propia: perfil, sesiones, logout, 2FA y cambio de contrasena propia.                                  |
| Autenticados con permiso | Endpoints con `@Permissions(...)` sin scope obligatorio; pueden usar `X-Company-Id` si el cliente selecciona compania. |
| Sistema                  | Administracion global, catalogos globales, RBAC y proxy tecnico Cardcloud.                                             |
| Compania                 | Modulos operativos que siempre dependen de `X-Company-Id`.                                                             |
| Sistema/compania         | Endpoints administrativos mixtos que pueden operar global o dentro de una compania.                                    |

## Permisos de modulo para frontend

Estos permisos no protegen endpoints por si solos. Sirven para que el frontend decida si un usuario puede ver y entrar a un modulo. Las acciones internas deben seguir usando permisos granulares como `users.create`, `users.access.assign`, `cards.update` o `documents.download`.

| Permiso                  | Modulo                   | Alcance recomendado | Uso esperado                                                 |
| ------------------------ | ------------------------ | ------------------- | ------------------------------------------------------------ |
| `companies.module`       | Empresas                 | Sistema/compania    | Mostrar entrada al modulo de empresas.                       |
| `sub-companies.module`   | Subempresas              | Compania            | Mostrar entrada al modulo de subempresas.                    |
| `drivers.module`         | Conductores              | Compania            | Mostrar entrada al modulo de conductores.                    |
| `fuels.module`           | Combustibles             | Sistema/compania    | Mostrar entrada al modulo de combustibles.                   |
| `vehicles.module`        | Vehiculos                | Compania            | Mostrar entrada al modulo de vehiculos.                      |
| `cards.module`           | Tarjetas                 | Compania            | Mostrar entrada al modulo de tarjetas.                       |
| `stations.module`        | Estaciones               | Compania            | Mostrar entrada al modulo de estaciones.                     |
| `station-fuels.module`   | Combustibles de estacion | Compania            | Mostrar entrada a la gestion de combustibles de estacion.    |
| `cardcloud-stock.module` | Stock Cardcloud          | Sistema/compania    | Mostrar entrada al modulo de stock local Cardcloud.          |
| `cardcloud.module`       | Cardcloud                | Sistema             | Mostrar entrada al modulo de operaciones externas Cardcloud. |
| `cardholders.module`     | Tarjetahabientes         | Compania            | Mostrar entrada al modulo administrativo de tarjetahabientes. |
| `cardholder.module`      | Tarjetahabiente          | Usuario conductor   | Mostrar entrada al modulo propio de tarjetahabiente.         |
| `users.module`           | Usuarios                 | Sistema/compania    | Mostrar entrada al modulo de usuarios.                       |
| `roles.module`           | Roles                    | Sistema             | Mostrar entrada al modulo de roles.                          |
| `permissions.module`     | Permisos                 | Sistema             | Mostrar entrada al modulo de permisos.                       |
| `documents.module`       | Documentos               | Compania            | Mostrar entrada al modulo de documentos.                     |
| `notifications.module`   | Notificaciones           | Sistema/compania    | Mostrar entrada al modulo de notificaciones.                 |

## CardholderController

Base path: `/api/cardholder`

Estos endpoints no usan `X-Company-Id`. El permiso RBAC permite entrar o ejecutar la accion, pero el alcance real se resuelve por `User.id -> Driver.userId -> Vehicle.driverId -> Card.vehicleId`. Para alta administrativa, el acceso recomendado del rol tarjetahabiente es `scopeKey: "subCompanyId"` con `scopeId` de la subcompania del conductor.

| Metodo  | Ruta                                      | Permiso                                | Alcance                       | Para que sirve                                    | Por que se necesita                                                            |

| `GET`   | `/api/cardholder/sub-company`             | `cardholder.sub-companies.read-one`    | Tarjetahabiente autenticado   | Consulta subcompania asociada al conductor.       | Permite mostrar contexto operativo propio sin exponer otras subcompanias.      |

## Observaciones

- Los endpoints `Publico` no requieren JWT ni permisos RBAC.
- Los endpoints `Autenticado propio` no usan permisos porque solo operan sobre recursos del usuario actual.
- Los endpoints `Sistema` requieren acceso global y no deben depender de `X-Company-Id`.
- Los endpoints `Compania` requieren `X-Company-Id`; el guard valida compania activa, acceso del usuario y scope por subcompania cuando aplica.
- Los endpoints `Sistema/compania` son mixtos: sin header operan globalmente; con header se limitan a la compania seleccionada.
- Los permisos de Cardcloud proxy son granulares porque algunos endpoints consultan datos sensibles o ejecutan operaciones contra el proveedor externo.
