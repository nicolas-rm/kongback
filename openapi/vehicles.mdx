## Base

Base path: `/api/vehicles`

Todos los endpoints requieren autenticacion y permisos `vehicles.*`. El borrado desactiva el registro cambiando `status` a `inactive`.

## Alcance por compania

Requiere header `X-Company-Id: <companyId>`. Todas las operaciones quedan limitadas a esa compania. Si el acceso del usuario tiene `scopeKey: "subCompanyId"`, `subCompanyId`, `driverId` y el vehiculo consultado tambien deben pertenecer a una de esas subcompanias.

## Endpoints

| Metodo   | Ruta                        | Permiso                      | Descripcion                              |
| -------- | --------------------------- | ---------------------------- | ---------------------------------------- |
| `POST`   | `/api/vehicles`             | `vehicles.create`            | Crea un vehiculo.                        |
| `GET`    | `/api/vehicles`             | `vehicles.read-list`         | Lista vehiculos.                         |
| `GET`    | `/api/vehicles/:id/drivers` | `vehicles.drivers.read-list` | Lista conductores asignados al vehiculo. |
| `GET`    | `/api/vehicles/:id`         | `vehicles.read-one`          | Obtiene un vehiculo.                     |
| `PATCH`  | `/api/vehicles/:id/driver`  | `vehicles.driver.assign`     | Asigna o quita conductor.                |
| `PATCH`  | `/api/vehicles/:id`         | `vehicles.update`            | Actualiza un vehiculo.                   |
| `DELETE` | `/api/vehicles/:id`         | `vehicles.delete`            | Desactiva un vehiculo.                   |

## Listado

`GET /api/vehicles`

Query params: `page`, `limit`, `search`, `all`, `status`, `subCompanyId`, `fuelId`, `driverId`.

`search` busca por `plates`, `economicNumber`, `model`, `subCompany.key`, `subCompany.name`, `fuel.code`, `fuel.name` y `driver.name`.

Para columnas visibles, usa `fuel.name`, `driver.name` y `subCompany.name`; conserva los IDs para filtros y acciones.

Response `200`: resultado paginado de `Vehicle` con `subCompany`, `fuel` y `driver` summaries.

## Crear

`POST /api/vehicles`

```json
{
    "subCompanyId": "79d03f1d-3da4-478e-806e-75ef9d86c992",
    "fuelId": "e9ef8b38-c983-4b9c-a51c-7d39ff7b1c84",
    "driverId": "d77d1344-93d4-4dc2-923a-b241185692de",
    "plates": "abc123",
    "economicNumber": "VH-001",
    "model": "Transit",
    "year": 2024,
    "odometerControl": true,
    "odometerInitial": 12500,
    "status": "active"
}
```

Requeridos: `subCompanyId`, `fuelId`, `plates`. `subCompanyId` debe estar activo y pertenecer a la compania enviada en `X-Company-Id`. `plates` se normaliza a mayusculas.

Opcionales: `driverId`, `economicNumber`, `model`, `year`, `odometerControl`, `odometerInitial`, `status`.

Response `201`: `Vehicle`.

## Obtener

`GET /api/vehicles/:id`

Path params: `id` UUID del vehiculo.

Response `200`: `Vehicle`.

## Conductores del vehiculo

`GET /api/vehicles/:id/drivers`

Permiso: `vehicles.drivers.read-list`.

Query params: `page`, `limit`, `search`, `all`, `status`.

`search` busca por `name`, `externalReference`, `subCompany.key`, `subCompany.name`, `user.username` y `user.fullName`.

Response `200`: resultado paginado de `Driver` con `subCompany` y `user` summaries.

Nota: el modelo actual guarda solo la relacion vigente `vehicle.driverId`; este endpoint devuelve cero o un conductor y no historial de asignaciones anteriores.

## Actualizar

`PATCH /api/vehicles/:id`

Acepta `fuelId`, `driverId`, `plates`, `economicNumber`, `model`, `year`, `odometerControl`, `odometerInitial`, `status`. `driverId` puede ser `null`.

Response `200`: `Vehicle` actualizado.

## Asignar conductor

`PATCH /api/vehicles/:id/driver`

```json
{
    "driverId": "d77d1344-93d4-4dc2-923a-b241185692de"
}
```

Usa `driverId: null` para quitar conductor. El vehiculo debe estar `active` y el conductor debe estar activo en la misma sub-compania. Si se envia `X-Company-Id`, ambos deben pertenecer a esa compania.

Response:

```json
{
    "id": "db28024c-9ed7-4318-84df-eb399ebd9e7e",
    "driverId": "d77d1344-93d4-4dc2-923a-b241185692de"
}
```

## Desactivar

`DELETE /api/vehicles/:id`

Response `200`:

```json
{
    "id": "db28024c-9ed7-4318-84df-eb399ebd9e7e",
    "status": "inactive"
}
```

## Notas para frontend

Este modulo tambien aplica las reglas CRUD de `Frontend Guidelines`: crear con campos visibles/derivados, editar solo campos documentados en `Actualizar`, confirmar desactivacion y refrescar el listado despues de cada mutacion.

### Capabilities para UI

Usa `GET /api/authentication/capabilities` para decidir entrada al menu y acciones visibles:

- Menu `Vehiculos`: `sidebar.vehicles.canEnter`.
- Pantalla `Vehiculos`: `modules.vehicles.canEnter`.
- Crear vehiculo: `modules.vehicles.actions.openCreate` y `modules.vehicles.actions.create`.
- Selector `Subcompania`: `modules.vehicles.actions.openSubCompanySelect`.
- Selector `Combustible`: `modules.vehicles.actions.openFuelSelect`.
- Selector `Conductor`: `modules.vehicles.actions.openDriverSelect`.
- Consultar listado: `modules.vehicles.actions.readList`.
- Refrescar listado: `modules.vehicles.actions.refreshList`.
- Configurar columnas: `modules.vehicles.actions.configureColumns`.
- Exportar listado desde el front: `modules.vehicles.actions.exportList`.
- Abrir detalle: `modules.vehicles.actions.openDetail` u `modules.vehicles.actions.openDetailDialog`.
- Editar vehiculo: `modules.vehicles.actions.openEdit` u `modules.vehicles.actions.openEditDialog`.
- Actualizar vehiculo: `modules.vehicles.actions.update`.
- Abrir modal `Asignar conductor`: `modules.vehicles.actions.openAssignDriver` u `modules.vehicles.actions.openAssignDriverDialog`.
- Guardar conductor asignado: `modules.vehicles.actions.assignDriver`.
- Quitar conductor: `modules.vehicles.actions.unassignDriver`.
- Abrir modal `Conductor actual`: `modules.vehicles.actions.openCurrentDriver` u `modules.vehicles.actions.openCurrentDriverDialog`.
- Consultar conductor actual: `modules.vehicles.actions.readDrivers`.
- Buscar conductores relacionados: `modules.vehicles.actions.searchDrivers`.
- Desactivar vehiculo: `modules.vehicles.actions.openDeactivate`, `modules.vehicles.actions.openDeactivateDialog` o `modules.vehicles.actions.deactivate`.

`configureColumns` y `exportList` no representan endpoints dedicados; son acciones de interfaz permitidas cuando el usuario puede consultar el listado. `download` existe como capability de compatibilidad para el permiso `vehicles.download`, pero este documento no define un endpoint `/api/vehicles/download`; si la pantalla descarga el listado general, debe exportar los datos cargados por el front o requerir un endpoint dedicado. `delete` en este modulo significa desactivar el vehiculo, no borrado fisico.

El front debe enviar `X-Company-Id`. `subCompanyId`, `fuelId` y `driverId` deben venir de selects filtrados por la compania seleccionada y por el alcance del usuario.

Campos recomendados para formularios:

- Subcompania: `subCompanyId`.
- Combustible: `fuelId`.
- Placas: `plates`.
- Numero economico: `economicNumber`, opcional.
- Modelo: `model`, opcional.
- Ano: `year`, opcional.
- Conductor: `driverId`, opcional.
- Control de odometro: `odometerControl`, toggle.
- Odometro inicial: `odometerInitial`, visible solo si aplica control de odometro.
- Estado: `status`, con `active` como valor inicial.

No muestres `fuelId`, `driverId` ni `subCompanyId` como campos de texto. En tablas usa `fuel.name`, `driver.name` y `subCompany.name`.

Cuando el usuario solo quiera asignar o quitar conductor, usa la accion dedicada `PATCH /api/vehicles/:id/driver`. Reserva `PATCH /api/vehicles/:id` para cambios generales del vehiculo.

Para consultar el conductor relacionado desde el detalle del vehiculo usa `GET /api/vehicles/:id/drivers`. No lo uses como historial; hoy representa la asignacion actual.

## Errores comunes

| Estado | Caso                                                                       |
| ------ | -------------------------------------------------------------------------- |
| `400`  | Datos relacionados no validos, anio fuera de rango o parametros invalidos. |
| `401`  | Request sin autenticacion valida.                                          |
| `403`  | Usuario autenticado sin el permiso requerido.                              |
| `404`  | Vehiculo no encontrado.                                                    |
| `409`  | Conflictos de unicidad segun constraints Prisma.                           |
