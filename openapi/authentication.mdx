## Base

Base path: `/api/authentication`

La API soporta autenticacion con cookies HttpOnly y tambien acepta `Authorization: Bearer <accessToken>` para el access token. En login, verificacion 2FA y refresh, el backend devuelve tokens en el body y ademas setea cookies `access_token` y `refresh_token`.

Para frontend web con cookies, usa requests con credenciales incluidas. Las mutaciones autenticadas con cookies requieren `Origin` o `Referer` permitido por la proteccion CSRF. Si se usa `Authorization: Bearer`, la proteccion CSRF no aplica.

## Tiempos de tokens y sesiones

Los tiempos son configurables por ambiente. Estos son los defaults actuales del backend:

| Concepto                   | Default | Configuracion                    | Uso                                                                                                    |
| -------------------------- | ------- | -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Access token               | `15m`   | `JWT_ACCESS_EXPIRES_IN`          | Vigencia del JWT usado en requests autenticados. Tambien aparece como `exp` en el payload.             |
| Refresh token              | `7d`    | `JWT_REFRESH_EXPIRES_IN`         | Vigencia maxima del JWT usado para renovar tokens. Se rota en cada `POST /api/authentication/refresh`. |
| Inactividad de sesion      | `60m`   | `SESSION_IDLE_TIMEOUT_MINUTES`   | Ventana sin actividad permitida antes de invalidar la sesion. Se expone como `idleExpiresAt`.          |
| Duracion total de sesion   | `7d`    | `SESSION_TOTAL_MINUTES`          | Limite absoluto de vida de la sesion aunque tenga actividad. Se expone como `expiresAt`.               |
| Actualizacion de actividad | `30s`   | `SESSION_TOUCH_INTERVAL_SECONDS` | Intervalo minimo para refrescar `lastActivityAt` e `idleExpiresAt` durante requests autenticados.      |

Una sesion deja de ser valida si fue revocada, si vence `expiresAt`, si vence `idleExpiresAt`, si el refresh token expiro o si el refresh token fue reutilizado despues de rotarse. Cuando esto ocurre, los endpoints protegidos o `refresh` responden `401` y el frontend debe limpiar el estado local de autenticacion.

## Modelos

### TokenResponse

```json
{
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIs...",
    "sessionId": "79b84132-20cc-4bf9-a4f0-3de3be656086"
}
```

| Campo          | Tipo     | Descripcion                                                                     |
| -------------- | -------- | ------------------------------------------------------------------------------- |
| `accessToken`  | `string` | JWT usado para autenticar requests. Tambien se guarda en cookie `access_token`. |
| `refreshToken` | `string` | JWT usado para renovar sesion. Tambien se guarda en cookie `refresh_token`.     |
| `sessionId`    | `string` | UUID v4 de la sesion activa.                                                    |

### JWT payload

El `accessToken` es un JWT firmado por el backend. Si el frontend lo decodifica, puede leer estos campos:

```json
{
    "sub": "9f5f0f4a-8f88-4f0b-9a18-6eb3f1e9b7a1",
    "username": "admin",
    "sessionId": "79b84132-20cc-4bf9-a4f0-3de3be656086",
    "iat": 1785796800,
    "exp": 1785797700
}
```

El `refreshToken` tambien es un JWT, pero solo incluye datos minimos de renovacion:

```json
{
    "sub": "9f5f0f4a-8f88-4f0b-9a18-6eb3f1e9b7a1",
    "sessionId": "79b84132-20cc-4bf9-a4f0-3de3be656086",
    "iat": 1785796800,
    "exp": 1786401600
}
```

| Campo       | Token            | Descripcion                                             |
| ----------- | ---------------- | ------------------------------------------------------- |
| `sub`       | Access y refresh | UUID v4 del usuario.                                    |
| `username`  | Solo access      | Nombre de usuario al momento de emitir el token.        |
| `sessionId` | Access y refresh | UUID v4 de la sesion asociada.                          |
| `iat`       | Access y refresh | Timestamp Unix en segundos en que fue emitido el token. |
| `exp`       | Access y refresh | Timestamp Unix en segundos en que expira el token.      |

El payload del JWT no incluye permisos, roles, companias disponibles, email, nombre completo ni banderas completas de perfil. Para esos datos usa `GET /api/authentication/me`, `GET /api/authentication/companies` y `GET /api/authentication/capabilities`. No uses el decode del token para autorizar menus, modulos o acciones.

### TwoFactorChallengeResponse

```json
{
    "requiresTwoFactor": true,
    "challengeToken": "c8b7c6c94fa14e1ebc1a6b62d37f5e84",
    "expiresInSeconds": 600,
    "expiresAt": "2026-08-03T21:10:00.000Z"
}
```

| Campo               | Tipo      | Descripcion                                                                |
| ------------------- | --------- | -------------------------------------------------------------------------- |
| `requiresTwoFactor` | `boolean` | Indica que el login necesita verificacion 2FA antes de emitir tokens.      |
| `challengeToken`    | `string`  | Token temporal que debe enviarse a `/api/authentication/2fa/verify-login`. |
| `expiresInSeconds`  | `number`  | Segundos de vigencia restantes al emitir el desafio.                       |
| `expiresAt`         | `string`  | Fecha ISO UTC en la que expira el desafio.                                 |

### Profile

```json
{
    "id": "9f5f0f4a-8f88-4f0b-9a18-6eb3f1e9b7a1",
    "username": "admin",
    "email": "admin@example.com",
    "fullName": "Admin User",
    "preferredLanguage": "es",
    "status": "active",
    "emailVerified": true,
    "requiresEmailVerification": false,
    "twoFactorEnabled": false,
    "mustChangePassword": false,
    "isGlobalAdmin": true,
    "companyIds": [],
    "sessionId": "79b84132-20cc-4bf9-a4f0-3de3be656086"
}
```

| Campo                       | Tipo                              | Descripcion                                                              |
| --------------------------- | --------------------------------- | ------------------------------------------------------------------------ |
| `id`                        | `string`                          | UUID v4 del usuario autenticado.                                         |
| `username`                  | `string`                          | Nombre de usuario.                                                       |
| `email`                     | `string`                          | Correo del usuario.                                                      |
| `fullName`                  | `string \| null`                  | Nombre completo.                                                         |
| `preferredLanguage`         | `string`                          | Idioma preferido para UI y correos.                                      |
| `status`                    | `active \| inactive \| suspended` | Estado operativo del usuario; en `/me` normalmente sera `active`.        |
| `emailVerified`             | `boolean`                         | Indica si el correo ya fue confirmado; derivado de `emailVerifiedAt`.    |
| `requiresEmailVerification` | `boolean`                         | Indica si la cuenta requiere verificacion antes de poder iniciar sesion. |
| `twoFactorEnabled`          | `boolean`                         | Indica si el usuario tiene 2FA activo.                                   |
| `mustChangePassword`        | `boolean`                         | Indica si debe cambiar contrasena antes de usar endpoints protegidos.    |
| `isGlobalAdmin`             | `boolean`                         | Indica si tiene acceso admin global.                                     |
| `companyIds`                | `string[]`                        | Companias a las que tiene acceso directo.                                |
| `sessionId`                 | `string \| null`                  | UUID v4 de la sesion activa cuando el token fue emitido con sesion.      |

### Session

```json
{
    "id": "79b84132-20cc-4bf9-a4f0-3de3be656086",
    "deviceName": "Chrome macOS",
    "userAgent": "Mozilla/5.0",
    "ipAddress": "127.0.0.1",
    "lastActivityAt": "2026-07-04T12:00:00.000Z",
    "idleExpiresAt": "2026-07-04T13:00:00.000Z",
    "expiresAt": "2026-07-05T12:00:00.000Z",
    "isCurrent": true
}
```

| Campo            | Tipo             | Descripcion                                                                  |
| ---------------- | ---------------- | ---------------------------------------------------------------------------- |
| `id`             | `string`         | UUID v4 de la sesion.                                                        |
| `deviceName`     | `string \| null` | Nombre del dispositivo detectado o enviado con `X-Device-Name`.              |
| `userAgent`      | `string \| null` | User-Agent registrado al crear la sesion.                                    |
| `ipAddress`      | `string \| null` | IP registrada al crear la sesion.                                            |
| `lastActivityAt` | `string`         | Fecha ISO UTC de la ultima actividad registrada.                             |
| `idleExpiresAt`  | `string`         | Fecha ISO UTC en la que la sesion vence por inactividad si no hay actividad. |
| `expiresAt`      | `string`         | Fecha ISO UTC de expiracion total de la sesion.                              |
| `isCurrent`      | `boolean`        | Indica si corresponde a la sesion actual segun la cookie `refresh_token`.    |

## Headers utiles

| Header                                | Uso                                                                                                                              |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `Authorization: Bearer <accessToken>` | Alternativa a cookie `access_token` para endpoints autenticados.                                                                 |
| `X-Company-Id`                        | UUID de la compania seleccionada. Requerido por endpoints operativos; opcional en endpoints mixtos como usuarios y capabilities. |
| `Accept-Language`                     | Idioma para validaciones, errores y correos cuando aplica.                                                                       |
| `X-Device-Name`                       | Nombre del dispositivo guardado al crear sesion con login o login 2FA.                                                           |
| `X-Forwarded-For`                     | IP de cliente usada para contexto de sesion si existe.                                                                           |
| `X-Request-Id`                        | ID de request opcional; el backend lo devuelve como response header.                                                             |

## Login

`POST /api/authentication/login`

Publico. Rate limit: 5 requests por 60 segundos.

### Body

```json
{
    "username": "admin",
    "password": "Secret123"
}
```

| Campo      | Tipo     | Requerido | Reglas                         |
| ---------- | -------- | --------- | ------------------------------ |
| `username` | `string` | Si        | Se recorta y colapsa espacios. |
| `password` | `string` | Si        | Se recorta y colapsa espacios. |

### Response `200`

Si el usuario no tiene 2FA activo, devuelve `TokenResponse` y setea cookies `access_token` y `refresh_token`.

Si el usuario tiene 2FA activo, limpia cookies existentes y devuelve `TwoFactorChallengeResponse`. Usa `expiresInSeconds` o `expiresAt` para mostrar el contador del desafio en frontend.

## Verificar login 2FA

`POST /api/authentication/2fa/verify-login`

Publico. Rate limit: 5 requests por 60 segundos.

### Body

Con codigo TOTP:

```json
{
    "challengeToken": "c8b7c6c94fa14e1ebc1a6b62d37f5e84",
    "code": "123456"
}
```

Con recovery code:

```json
{
    "challengeToken": "c8b7c6c94fa14e1ebc1a6b62d37f5e84",
    "recoveryCode": "ABCD-EFGH"
}
```

| Campo            | Tipo     | Requerido   | Reglas                                                                                         |
| ---------------- | -------- | ----------- | ---------------------------------------------------------------------------------------------- |
| `challengeToken` | `string` | Si          | Token devuelto por `POST /api/authentication/login` cuando `requiresTwoFactor` es `true`.      |
| `code`           | `string` | Condicional | Codigo TOTP. Requerido si no se envia `recoveryCode`.                                          |
| `recoveryCode`   | `string` | Condicional | Recovery code de un solo uso. Requerido si no se envia `code`. Acepta formato con o sin guion. |

### Response `200`

Devuelve `TokenResponse` y setea cookies `access_token` y `refresh_token`. Si se usa `recoveryCode`, el backend lo marca como usado y no puede reutilizarse.

## Registro

`POST /api/authentication/register`

Publico. Rate limit: 3 requests por 60 segundos.

### Body

```json
{
    "username": "admin",
    "email": "admin@example.com",
    "fullName": "Admin User",
    "password": "Secret123"
}
```

| Campo      | Tipo     | Requerido | Reglas                                                         |
| ---------- | -------- | --------- | -------------------------------------------------------------- |
| `username` | `string` | Si        | Se recorta y colapsa espacios.                                 |
| `email`    | `string` | Si        | Se recorta, colapsa espacios y normaliza a minusculas.         |
| `fullName` | `string` | Si        | Se recorta y colapsa espacios.                                 |
| `password` | `string` | Si        | Minimo 8 caracteres, una minuscula, una mayuscula y un numero. |

### Response `200`

```json
{
    "id": "9f5f0f4a-8f88-4f0b-9a18-6eb3f1e9b7a1",
    "registered": true,
    "emailVerificationRequired": true,
    "expiresInSeconds": 3600,
    "expiresAt": "2026-08-03T22:00:00.000Z"
}
```

`expiresInSeconds` y `expiresAt` corresponden al enlace de verificacion enviado por correo.

## Refresh

`POST /api/authentication/refresh`

Publico. Rate limit: 20 requests por 60 segundos.

El refresh token puede enviarse en el body o venir desde la cookie `refresh_token`. El backend revoca el refresh token usado, actualiza actividad de sesion y emite nuevos tokens. Si el refresh token, la duracion total de sesion o la ventana de inactividad ya vencieron, responde `401`.

### Body

```json
{
    "refreshToken": "eyJhbGciOiJIUzI1NiIs..."
}
```

| Campo          | Tipo     | Requerido | Reglas                                     |
| -------------- | -------- | --------- | ------------------------------------------ |
| `refreshToken` | `string` | No        | Opcional si existe cookie `refresh_token`. |

### Response `200`

Devuelve `TokenResponse` y actualiza cookies `access_token` y `refresh_token`.

## Logout

`POST /api/authentication/logout`

Autenticado.

Limpia cookies de autenticacion. Si el request trae cookie `refresh_token`, revoca la sesion asociada a ese refresh token. Si no trae refresh cookie, el comportamiento actual del servicio revoca todas las sesiones del usuario autenticado.

### Response `200`

```json
{
    "revokedSessions": 1
}
```

## Logout all

`POST /api/authentication/logout-all`

Autenticado.

Revoca todas las sesiones del usuario y limpia cookies.

### Response `200`

```json
{
    "revokedSessions": 3
}
```

## Perfil actual

`GET /api/authentication/me`

Autenticado. Este endpoint se puede usar aunque `mustChangePassword` sea `true`.

Header opcional: `X-Company-Id: <companyId>`. Si se envia, `capabilities` se calcula para esa compania seleccionada.

### Response `200`

Devuelve `Profile` con `capabilities` calculadas para el contexto actual. Para refrescar permisos sin recargar el perfil completo, usa `GET /api/authentication/capabilities`.

## Listar companias

`GET /api/authentication/companies`

Autenticado. Este endpoint se puede usar aunque `mustChangePassword` sea `true`.

Devuelve las companias que el usuario puede seleccionar en el front. Un admin global recibe todas las companias activas con `isGlobalAdmin: true`; un usuario normal recibe solo las companias donde tiene accesos activos.

### Response `200`

Devuelve `CompanyAccess[]`.

## Consultar capacidades

`GET /api/authentication/capabilities`

Autenticado. Este endpoint se puede usar aunque `mustChangePassword` sea `true`.

Header opcional: `X-Company-Id: <companyId>`. Si se envia, el backend valida que la compania exista, este activa y sea accesible para el usuario antes de calcular permisos. Si se omite, calcula solo permisos de acceso global (`companyId: null`).

Este endpoint es el contrato recomendado para renderizar sidebar, modulos y acciones. Sin `X-Company-Id` representa modo global; con `X-Company-Id` representa la compania seleccionada.

Si los permisos vienen de un acceso con `scopeKey: "subCompanyId"`, los endpoints operativos aplican ese scope al consultar, crear, actualizar o eliminar datos. `capabilities` devuelve permisos; el filtrado fino de datos se aplica en cada endpoint.

Para mostrar el modulo propio de tarjetahabiente, si el acceso vive en una compania/subcompania, consulta `capabilities` con `X-Company-Id` de esa compania para obtener `cardholderCards`, `cardholderVehicles` y `cardholderWork`. Las rutas `/api/cardholder/*` siguen sin usar `X-Company-Id`; solo usan el usuario autenticado y su conductor vinculado.

Los permisos de endpoints de sistema, como `companies.create`, `companies.update`, acciones globales de `users`, `roles.*`, `permissions.*` y mutaciones de `fuels`, solo se devuelven si el usuario los tiene en un acceso global (`companyId: null`).

### Response `200`

Devuelve `Capabilities`.

Ejemplo:

```json
{
    "companyId": "company-id",
    "isGlobalAdmin": false,
    "permissions": ["users.module", "users.read-list", "users.create"],
    "sidebar": {
        "users": {
            "canEnter": true,
            "label": "Usuarios",
            "path": "/administration/users",
            "section": "administracion"
        }
    },
    "modules": {
        "users": {
            "canEnter": true,
            "permissions": ["users.module", "users.read-list", "users.create"],
            "actions": {
                "openCreate": true,
                "create": true,
                "readList": true,
                "refreshList": true,
                "configureColumns": true,
                "exportList": true,
                "openDetailDrawer": false,
                "readOne": false,
                "openEditModal": false,
                "update": false,
                "openAccessModal": false,
                "assignAccess": false,
                "replaceAccess": false,
                "readAccess": false,
                "openPermissionsTab": false,
                "readPermissions": false,
                "openChangePasswordModal": false,
                "openResendCredentialsModal": false,
                "openUnlinkTwoFactorModal": false
            }
        }
    }
}
```

`sidebar` solo debe usarse para pintar navegacion. `modules` debe usarse para botones, acciones, formularios, descargas y flujos internos.

## Heartbeat

`POST /api/authentication/heartbeat`

Autenticado. Este endpoint se puede usar aunque `mustChangePassword` sea `true`.

Sirve como ping autenticado para confirmar que la sesion sigue vigente. Al pasar por el guard JWT, tambien participa en la actualizacion de actividad de sesion segun `SESSION_TOUCH_INTERVAL_SECONDS`.

### Response `200`

```json
{
    "ok": true,
    "userId": "9f5f0f4a-8f88-4f0b-9a18-6eb3f1e9b7a1",
    "sessionId": "79b84132-20cc-4bf9-a4f0-3de3be656086"
}
```

## Actualizar perfil

`PATCH /api/authentication/me`

Autenticado. Si `mustChangePassword` es `true`, este endpoint queda bloqueado por el guard global hasta cambiar la contrasena.

Si `email` cambia respecto al correo actual, el backend marca el nuevo correo como no verificado (`emailVerified: false`, `requiresEmailVerification: true`) y envia automaticamente un correo de verificacion al nuevo email.

### Body

Todos los campos son opcionales.

```json
{
    "email": "admin@example.com",
    "fullName": "Admin User",
    "preferredLanguage": "es"
}
```

| Campo               | Tipo     | Reglas                                                 |
| ------------------- | -------- | ------------------------------------------------------ |
| `email`             | `string` | Se recorta, colapsa espacios y normaliza a minusculas. |
| `fullName`          | `string` | Se recorta y colapsa espacios.                         |
| `preferredLanguage` | `string` | Se recorta, colapsa espacios y normaliza a minusculas. |

### Response `200`

```json
{
    "id": "9f5f0f4a-8f88-4f0b-9a18-6eb3f1e9b7a1",
    "username": "admin",
    "email": "admin@example.com",
    "fullName": "Admin User",
    "preferredLanguage": "es",
    "emailVerified": true,
    "requiresEmailVerification": false
}
```

## Listar sesiones

`GET /api/authentication/sessions`

Autenticado. Este endpoint se puede usar aunque `mustChangePassword` sea `true`.

### Response `200`

Devuelve `Session[]` con sesiones no revocadas, no vencidas por duracion total y no vencidas por inactividad.

## Revocar sesion

`DELETE /api/authentication/sessions/:sessionId`

Autenticado. Este endpoint se puede usar aunque `mustChangePassword` sea `true`.

Si se revoca la sesion actual, el backend limpia cookies.

### Path params

| Parametro   | Tipo   | Descripcion                |
| ----------- | ------ | -------------------------- |
| `sessionId` | `uuid` | ID de la sesion a revocar. |

### Response `200`

```json
{
    "id": "79b84132-20cc-4bf9-a4f0-3de3be656086",
    "revoked": true,
    "revokedCurrent": false
}
```

## Cambiar contrasena

`PATCH /api/authentication/password`

Autenticado. Rate limit: 5 requests por 60 segundos. Este endpoint se puede usar aunque `mustChangePassword` sea `true`.

Al cambiar la contrasena, el backend revoca sesiones del usuario y limpia cookies. El frontend debe enviar al usuario a login al recibir respuesta exitosa.

### Body

```json
{
```

## Flujo recomendado para frontend

1. Llamar `POST /api/authentication/login`.
2. Si responde `requiresTwoFactor: true`, pedir codigo TOTP y llamar `POST /api/authentication/2fa/verify-login`.
3. Guardar estado de sesion desde cookies o desde `TokenResponse`, segun estrategia del cliente.
4. Llamar `GET /api/authentication/me` para obtener identidad, `companyIds` y `mustChangePassword`.
5. Llamar `GET /api/authentication/companies`, permitir que el usuario seleccione compania y enviar su `id` como `X-Company-Id` en endpoints operativos.
6. Llamar `GET /api/authentication/capabilities` con `X-Company-Id` para renderizar modulos y acciones disponibles para la compania seleccionada.
7. Si `mustChangePassword` es `true`, limitar la UI a cambio de contrasena, logout, ver perfil, companias y endpoints marcados como permitidos arriba.
8. Renovar sesion con `POST /api/authentication/refresh` cuando expire el access token. Si `refresh` responde `401`, limpiar estado local y enviar a login.

Para construir formularios desde esta documentacion, aplica tambien las reglas de `Frontend Guidelines`: no todos los campos del contrato deben mostrarse como controles visibles; algunos se omiten por default, se derivan del contexto o se traducen a nombres de UI.

## Notas para frontend

Este modulo no es CRUD de catalogo, pero aplica las reglas de `Frontend Guidelines` para formularios y acciones: renderiza solo campos necesarios, no persistas secretos, confirma acciones sensibles y refresca estado de sesion, companias o capacidades despues de mutaciones.

No generes una pagina de menu llamada `authentication`. Estos endpoints deben alimentar pantallas o componentes concretos: login, perfil, seguridad, sesiones, recuperacion de contrasena, selector de compania y carga de capacidades.

Para aplicaciones web, prefiere cookies HttpOnly con requests usando credenciales incluidas. Si usas cookies, no necesitas guardar tokens en storage del navegador.

Para timers y expiracion de sesion:

- Usa `exp` del access token solo para saber cuando intentar renovar con `POST /api/authentication/refresh`.
- Usa `GET /api/authentication/sessions` para mostrar sesiones activas, `lastActivityAt`, expiracion por inactividad (`idleExpiresAt`) y expiracion total (`expiresAt`).
- No calcules autorizacion, modulos ni acciones desde tiempos del token; usa `GET /api/authentication/me` y `GET /api/authentication/capabilities`.
- Si una llamada protegida o `refresh` responde `401`, trata la sesion como invalida y limpia el estado local de autenticacion.

Campos y datos que no deben mostrarse o persistirse como datos de UI normal:

- `accessToken` y `refreshToken`: si usas cookies, tratarlos como detalle tecnico de respuesta.
- `challengeToken`: conservarlo solo durante el flujo 2FA.
- `recoveryCodes`: mostrarlos una sola vez al usuario y no persistirlos en estado global.
- `otpAuthenticationUrl` y `secret`: usarlos solo para configurar 2FA.

Para seleccion de compania:

- Usa `GET /api/authentication/companies` para llenar el selector.
- Guarda internamente el `id` seleccionado y mandalo como `X-Company-Id`.
- Muestra `name` y `key`; no muestres el UUID como etiqueta principal.
- Despues de cambiar compania, vuelve a consultar `GET /api/authentication/capabilities` con el nuevo header.

Para UI de permisos, usa `capabilities.modules.<modulo>.actions` como contrato principal para acciones visibles. Mantén `capabilities.permissions` como lista plana de compatibilidad o diagnostico; no infieras permisos por rol visible ni por nombre de usuario.

## Errores comunes

| Estado | Caso                                                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `400`  | Body invalido, token de reset/verificacion invalido, codigo 2FA invalido o configuracion 2FA expirada.                         |
| `401`  | Login no valido, sesion no valida, sesion vencida, sesion vencida por inactividad o cierre preventivo de sesion por seguridad. |
| `403`  | CSRF rechazado o usuario con `mustChangePassword` intentando usar endpoints bloqueados.                                        |
| `409`  | Conflictos de unicidad como `username` o `email` duplicados, segun el filtro Prisma global.                                    |
| `429`  | Rate limit excedido en endpoints protegidos con throttling.                                                                    |
