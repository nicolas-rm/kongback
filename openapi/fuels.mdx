## Base

Base path: `/api/fuels`

Todos los endpoints requieren autenticacion y permisos `fuels.*`. El borrado desactiva el registro cambiando `status` a `inactive`.

El catalogo de combustibles es global. Los endpoints de lectura pueden usarse como catalogo de referencia desde modulos operativos. Crear, actualizar y desactivar combustibles requiere acceso global; no se ejecuta dentro de `X-Company-Id`.

## Modelo

```json
{
    "id": "e9ef8b38-c983-4b9c-a51c-7d39ff7b1c84",
    "code": "DIESEL",
    "name": "Diesel",
    "status": "active"
}
```

## Endpoints

| Metodo   | Ruta             | Permiso           | Descripcion               |
| -------- | ---------------- | ----------------- | ------------------------- |
| `POST`   | `/api/fuels`     | `fuels.create`    | Crea un combustible.      |
| `GET`    | `/api/fuels`     | `fuels.read-list` | Lista combustibles.       |
| `GET`    | `/api/fuels/export` | `fuels.read-list` | Exporta combustibles filtrados. |
| `GET`    | `/api/fuels/:id` | `fuels.read-one`  | Obtiene un combustible.   |
| `PATCH`  | `/api/fuels/:id` | `fuels.update`    | Actualiza un combustible. |
| `DELETE` | `/api/fuels/:id` | `fuels.delete`    | Desactiva un combustible. |

## Listado

`GET /api/fuels`

Query params: `page`, `limit`, `search`, `all`, `status`.

`search` busca por `code` y `name`.

Response `200`: resultado paginado de `Fuel`.

## Exportar combustibles

`GET /api/fuels/export`

Requiere `fuels.read-list`.

Query params: acepta los mismos filtros de `GET /api/fuels` mas `format`.

`format`: `xlsx`, `excel`, `csv`, `txt` o `pdf`. Default `xlsx`.

Response `200`: archivo descargable. El backend aplica filtros igual que el listado, ignora paginacion y limita la exportacion a `5000` filas.

## Crear

`POST /api/fuels`

```json
{
    "code": "diesel",
    "name": "Diesel",
    "status": "active"
}
```

Requeridos: `code`, `name`. `code` se normaliza a mayusculas.

Opcional: `status`.

Requiere acceso global.

Response `201`: `Fuel`.

## Obtener

`GET /api/fuels/:id`

Path params: `id` UUID del combustible.

Response `200`: `Fuel`.

## Actualizar

`PATCH /api/fuels/:id`

Acepta `code`, `name` y `status`, todos opcionales.

Requiere acceso global.

Response `200`: `Fuel` actualizado.

## Desactivar

`DELETE /api/fuels/:id`

Requiere acceso global.

Response `200`:

```json
{
    "id": "e9ef8b38-c983-4b9c-a51c-7d39ff7b1c84",
    "status": "inactive"
}
```

## Notas para frontend

Este modulo tambien aplica las reglas CRUD de `Frontend Guidelines`: crear con campos visibles/derivados, editar solo campos documentados en `Actualizar`, confirmar desactivacion y refrescar el listado despues de cada mutacion.

### Capabilities para UI

Usa `GET /api/authentication/capabilities` para decidir entrada al menu y acciones visibles:

- Menu `Combustibles`: `sidebar.fuels.canEnter`.
- Pantalla `Combustibles`: `modules.fuels.canEnter`.
- Crear combustible: `modules.fuels.actions.openCreate` u `modules.fuels.actions.openCreateDialog`, y `modules.fuels.actions.create`.
- Consultar listado: `modules.fuels.actions.readList`.
- Refrescar listado: `modules.fuels.actions.refreshList`.
- Configurar columnas: `modules.fuels.actions.configureColumns`.
- Exportar listado: `modules.fuels.actions.exportList`.
- Abrir detalle: `modules.fuels.actions.openDetail` u `modules.fuels.actions.openDetailDialog`.
- Consultar detalle: `modules.fuels.actions.readOne`.
- Editar combustible: `modules.fuels.actions.openEdit` u `modules.fuels.actions.openEditDialog`.
- Actualizar combustible: `modules.fuels.actions.update`.
- Desactivar combustible: `modules.fuels.actions.openDeactivate`, `modules.fuels.actions.openDeactivateDialog` o `modules.fuels.actions.deactivate`.

`configureColumns` es accion local de interfaz. `exportList` usa `GET /api/fuels/export` y se habilita cuando el usuario puede consultar el listado. `delete` en este modulo significa desactivar el combustible, no borrado fisico.

Este catalogo es global. No envies `X-Company-Id` para crear, actualizar o desactivar combustibles.

La pantalla de combustibles es opcional segun permisos/producto. Si el usuario no administra catalogos globales, usa `GET /api/fuels` solo como fuente de selects para vehiculos, tarjetas y combustibles disponibles en estaciones.

El seed base carga estos combustibles iniciales:

| Code               | Nombre                |
| ------------------ | --------------------- |
| `GASOLINE_REGULAR` | Gasolina Regular      |
| `GASOLINE_PREMIUM` | Gasolina Premium      |
| `DIESEL`           | Diesel                |
| `DIESEL_UBA`       | Diesel UBA            |
| `LPG`              | Gas LP                |
| `CNG`              | Gas Natural Vehicular |
| `ELECTRIC`         | Electrico             |
| `BIODIESEL`        | Biodiesel             |
| `ETHANOL_E85`      | Etanol E85            |
| `HYDROGEN`         | Hidrogeno             |

Campos recomendados para formularios:

- Codigo: `code`.
- Nombre: `name`.
- Estado: `status`, con `active` como valor inicial.

El `code` se normaliza a mayusculas en backend. En formularios puedes transformar visualmente a mayusculas, pero conserva la validacion del backend como fuente de verdad.

En modulos operativos, usa combustibles activos como opciones de select y muestra `name` con `code` como apoyo visual.

## Errores comunes

| Estado | Caso                                                                              |
| ------ | --------------------------------------------------------------------------------- |
| `400`  | Body, query o path params invalidos.                                              |
| `401`  | Request sin autenticacion valida.                                                 |
| `403`  | Usuario autenticado sin el permiso requerido o sin acceso global para mutaciones. |
| `404`  | Combustible no encontrado.                                                        |
| `409`  | Conflictos de unicidad segun constraints Prisma.                                  |
